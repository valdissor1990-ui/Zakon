# Входные записи для сборки базы

Агент принимает только подготовленные структурированные записи. Он не сочиняет правовые тексты и не превращает поисковые сниппеты в нормативные документы.

Файл records.json должен содержать:
- release: version, version_code, created_at, effective_as_of;
- sources: уникальные ключи захватов, поле registry_id с ID разрешённого портала из content/sources/registry.json, реквизиты источника и SHA-256 сохранённого оригинала;
- documents: реквизиты документа, статус, primary_source_key, контрольную сумму нормализованного текста, список статей, перекрёстных ссылок, source_checks и status_history. Записи status_history обязаны ссылаться на сохранённый источник через source_key; периоды действия статусов не должны пересекать даты в обратном порядке.

Первый SQLite-выпуск должен иметь version_code не ниже 7, чтобы обновить пользователей прежних JSON-пакетов (версии доходили до 6). Далее version_code строго возрастает при каждой публикации. Человекочитаемая версия может быть семантической.

Для каждого источника сборщик требует сохранённый оригинал `content/evidence/<source-key>/<sha256>.source` и соответствующий JSON-файл метаданных, созданные `agent/capture_sources.py`. Проверяются байты файла, SHA-256, запрошенный и конечный HTTPS-адрес, время получения и метаданные. Одного вручную указанного хеша недостаточно. Оригиналы и sidecar-метаданные должны попасть в репозиторий до сборки выпуска.

Для каждого документа обязательно не менее трёх разных государственных информационных систем с результатом match; эти системы должны относиться как минимум к двум разным операторам. Один портал может иметь отдельные захваты для разных документов; уникальный key не должен повторяться. Недоступный источник, расхождение, отсутствие хеша или нерешённая редакция останавливают сборку.

Даже структурно прошедшая сборка получает статус draft. Публикация запускается вручную через GitHub Actions и должна проходить approval в GitHub Environment legal-content-approval. Автоматическая сверка не заменяет юридическую экспертизу.


## Каталог первой очереди

Приоритетный перечень федеральных актов ведётся в `content/catalog/core-federal-acts.json`. Это только список работ и поисковые реквизиты, не тексты норм. Каждая запись остаётся `not_imported` до загрузки официального оригинала, проверки редакции и ручного утверждения. Один и тот же государственный портал может иметь несколько захватов — отдельный `key` на каждый документ и `registry_id` для источника из реестра.


В каталоге у каждой записи есть `metadata_status`: `provisional` означает, что даже реквизиты ещё требуют сверки; `source_reference_verified` означает, что наименование и реквизиты сверены по указанной официальной странице, но полный действующий текст всё равно не импортирован. Ни один из этих статусов не означает, что документ уже включён в базу.
