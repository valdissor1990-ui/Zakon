# Входные записи для сборки базы

Агент принимает только подготовленные структурированные записи. Он не сочиняет правовые тексты и не превращает поисковые сниппеты в нормативные документы.

Файл records.json должен содержать:
- release: version, version_code, created_at, effective_as_of;
- sources: уникальные ключи, совпадающие с ID в content/sources/registry.json, реквизиты источника и SHA-256 сохранённого оригинала;
- documents: реквизиты документа, статус, primary_source_key, контрольную сумму нормализованного текста, список статей, перекрёстных ссылок и source_checks.

Первый SQLite-выпуск должен иметь version_code не ниже 7, чтобы обновить пользователей прежних JSON-пакетов (версии доходили до 6). Далее version_code строго возрастает при каждой публикации. Человекочитаемая версия может быть семантической.

Для каждого документа обязательно не менее трёх независимых источников с результатом match. Недоступный источник, расхождение, отсутствие хеша или нерешённая редакция останавливают сборку.

Даже структурно прошедшая сборка получает статус draft. Публикация запускается вручную через GitHub Actions и должна проходить approval в GitHub Environment legal-content-approval. Автоматическая сверка не заменяет юридическую экспертизу.
