# Безопасность личного кабинета «ЗаконЪ»

Документ описывает **реализованную** модель защиты, а не только план.

## Что защищено

| Данные | Как хранятся |
|--------|----------------|
| Пароль (PIN) | Не хранится. Хранятся `pin_salt` + `pin_verifier` = PBKDF2-HMAC-SHA256 (600 000 итераций, 32 байта), сравнение за постоянное время |
| Список дел (JSON) | AES-256-GCM, ключ в Android Keystore, поле `cases_enc` |
| Вложения | Копируются в `files/cabinet_enc/*.enc`, AES-256-GCM; в деле — только имя файла |
| Временный просмотр | Расшифровка в `cache/cabinet_view/`, очистка при выходе из кабинета |

## Ключ

- Алгоритм: AES-256-GCM (`AES/GCM/NoPadding`)
- Хранилище: Android Keystore, alias `zakon_cabinet_aes_v1`, ключ неэкспортируемый
- StrongBox запрашивается на API 28+, при отказе — обычный TEE/Keystore
- На API 30+ для ключа может требоваться недавняя системная аутентификация (биометрия / PIN устройства), validity ~5 минут
- Уровень ключа показывается в UI кабинета (StrongBox / TEE / Software)

## Биометрия

- `BiometricPrompt` с `BIOMETRIC_STRONG | BIOMETRIC_WEAK`
- При возможности передаётся `CryptoObject` (Cipher из Keystore)
- Биометрия — удобный вход; пароль остаётся запасным каналом
- Отказ/ошибка биометрии не раскрывает данные дел

## Анти-брутфорс

- Счётчик неудачных попыток PIN
- Прогрессивная задержка: после 3+ ошибок 1–60 с, после 8 ошибок — 5 минут
- Поля ввода блокируются на время lockout

## Миграция со старых версий

- Старый `pin_hash` (`String.hashCode`) принимается один раз; при успехе пароль пересохраняется в PBKDF2, legacy-ключ удаляется
- Старый plaintext `cases_json` при первом успешном чтении перешифровывается в `cases_enc` и удаляется

## Ограничения (честно)

- Внешнее приложение-просмотрщик получает временный URI и теоретически может сохранить копию
- Root, malware с правами на unlocked-устройство, accessibility и screen capture вне границы защиты приложения
- Удаление данных приложения / uninstall уничтожает Keystore-ключ → зашифрованные данные кабинета невосстановимы
- Юридическая база кодексов **не** шифруется этим контуром (справочный публичный контент)

## Проверка перед релизом

1. Создать PIN → закрыть приложение → войти PIN и биометрией
2. Неверный PIN → растущая задержка
3. Создать дело, вложить фото и PDF → переустановить не удаляя data (если debug) / просто перезапуск → данные на месте
4. Выйти из кабинета → убедиться, что cache view очищается
5. Устройство без StrongBox и с StrongBox
6. Миграция с установки, где ещё был `pin_hash`
