# Безопасность личного кабинета «ЗаконЪ»

## Главный принцип

**Пароль (код) никогда не сохраняется** ни в открытом, ни в обратимо зашифрованном виде.
На диске нет строки, из которой можно «достать пароль».

Хранится только:

| Поле | Смысл |
|------|--------|
| `pin_salt` | Случайные 16 байт |
| `pin_verifier` | PBKDF2-HMAC-SHA256(password, salt, 600 000) → 32 байта |
| `pin_enabled` | Флаг: требовать пароль при входе или нет |

Даже эти поля лежат в **EncryptedSharedPreferences** (AES-256-SIV ключи + AES-256-GCM значения), ключ MasterKey — в **Android Keystore**.

Дампа XML/prefs **недостаточно**, чтобы прочитать salt/verifier: нужна компрометация Keystore (обычно TEE/StrongBox) на разблокированном устройстве.

## Почему offline-bruteforce тяжел

1. Нужен доступ к расшифрованным EncryptedSharedPreferences (Keystore).
2. Затем перебор PIN против PBKDF2-HMAC-SHA256 **600 000** итераций на попытку.
3. Короткий PIN всё же уязвим при очень мощном офлайн-переборе после взлома Keystore — поэтому минимум **6 символов**, лучше длинная фраза.
4. В приложении — прогрессивная блокировка попыток (до 5 минут).

Старый `pin_hash = String.hashCode()` при миграции **удаляется навсегда** и больше не используется.

## Данные дел

- JSON дел: AES-256-GCM, ключ Keystore (`zakon_cabinet_aes_v1`), хранение в secure prefs как `cases_enc`.
- Вложения: файлы `files/cabinet_enc/*.enc`, тот же AES-GCM.
- Просмотр: временная расшифровка в cache, очистка при выходе.

Отключение пароля **не расшифровывает** дела: на диске они остаются ciphertext. Отключается только UI-замок входа.

## Управление кодом (в приложении → Кабинет → «Код»)

| Действие | Что происходит |
|----------|----------------|
| Отключить пароль | `pin_enabled=false`, verifier остаётся; вход без запроса до повторного включения |
| Включить пароль | Снова требовать тот же verifier |
| Сменить пароль | Новый salt+verifier; старый verifier перезаписывается |
| Удалить пароль | salt+verifier стираются; пароль невосстановим |
| Удалить пароль и все дела | + wipe cases и encrypted files |

Все операции удаления/отключения требуют **текущий пароль**.

## Биометрия

`BiometricPrompt` + по возможности `CryptoObject` (Cipher Keystore). Не заменяет криптографию дел.

## Ограничения

- Root / malware на разблокированном устройстве вне модели угроз приложения.
- Внешний viewer вложения может сохранить временную копию.
- Uninstall / clear data уничтожает Keystore-ключи → данные кабинета невосстановимы.
- Юридическая база кодексов не шифруется этим контуром.
