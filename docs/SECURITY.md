# Безопасность личного кабинета «ЗаконЪ»

## Защита пароля приложения

Пароль приложения не сохраняется. Хранятся только:
- случайная соль;
- PBKDF2-HMAC-SHA256 verifier (600 000 итераций, 32 байта);
- флаг включения блокировки.

Минимальная длина пароля — 8 символов. После нескольких неверных попыток включается прогрессивная блокировка.

Эти значения находятся в EncryptedSharedPreferences (AES-256-SIV для ключей и AES-256-GCM для значений), мастер-ключ хранится в Android Keystore.

## Шифрование данных кабинета

- JSON рабочего пространства шифруется AES-256-GCM.
- Ключ AES-256 создаётся в Android Keystore и не экспортируется.
- StrongBox используется, если устройство поддерживает его.
- Вложения хранятся как AES-GCM ciphertext в приватном каталоге приложения.
- Временные расшифрованные файлы находятся только в ограниченном каталоге cache/cabinet_view и удаляются при закрытии/сворачивании кабинета.

## Аутентификация ключа по версии Android

- **Android 11 и новее:** ключ требует недавнюю системную аутентификацию. Разрешены сильная биометрия или системный PIN/пароль/графический ключ устройства. Приложение должно запускать соответствующий BiometricPrompt перед использованием ключа.
- **Android 6–10:** для новых ключей не включается биометрическая привязка Keystore, поскольку системный PIN не является паролем приложения и старый экран входа не мог надёжно передать Keystore-токен. Доступ к кабинету контролируется PBKDF2-паролем приложения; AES-ключ остаётся неэкспортируемым в Keystore.
- Старые ключи сохраняют исходную политику аутентификации. Если такой ключ требует биометрию, а на устройстве она недоступна, пароль приложения сам по себе не сможет расшифровать данные. Не удаляйте данные и не переустанавливайте приложение — сначала настройте системную аутентификацию или восстановите резервную копию.

## Ограничения

- Root-доступ и вредоносное ПО на разблокированном устройстве находятся вне модели угроз приложения.
- Внешнее приложение-просмотрщик может сохранить временную копию открытого вложения.
- Удаление приложения/очистка данных уничтожает Keystore-ключи; зашифрованные данные без резервной копии восстановить нельзя.
- Удалённый JSON-пакет правовой базы не является криптографически подписанным выпуском: SHA-256 из того же репозитория защищает от случайного повреждения, но не от компрометации репозитория. Для production-базы нужна подпись манифеста и закреплённый публичный ключ.

## Файлы реализации

- `CabinetPinKdf.kt` — PBKDF2 и сравнение verifier.
- `CabinetCrypto.kt` — AES-GCM, Keystore и вложения.
- `CabinetData.kt` — защищённое хранилище и миграции.
- `UtilityScreens.kt` — вход, биометрия и PIN-интерфейс.
