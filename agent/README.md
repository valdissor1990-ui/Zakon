# Агент подготовки правовой базы

Агент предназначен для воспроизводимого процесса: получение документов из официальных источников, сохранение исходных копий и реквизитов, нормализация структуры, межисточниковая сверка, валидация и подготовка выпуска.

## Жёсткие правила

- Не генерировать отсутствующий текст нормы.
- Не считать совпадение заголовков доказательством совпадения редакций.
- Сохранять URL, время получения, реквизиты публикации и SHA-256 исходного файла.
- Различать дату принятия, официального опубликования и вступления в силу.
- При расхождении источников отправлять документ на ручную проверку.
- Не публиковать выпуск при ошибках целостности или неполной проверке.

`capture_sources.py` сохраняет исходные файлы по URL из подготовленных records.json. Он принимает только HTTPS-хосты из registry.json, проверяет хост каждого перенаправления, ограничивает размер файла и записывает SHA-256 и метаданные получения. Скрипт не распознаёт HTML/PDF, не извлекает нормы и не меняет records.json: юридическое структурирование и сверка выполняются отдельно человеком.

## pravo.gov.ru — автоматизация и ограничения

### Проблема

Эндпоинт `https://pravo.gov.ru/proxy/ips/` (интегрированный банк) **часто недоступен с IP-адресов вне РФ**. GitHub Actions и большинство зарубежных VPS получают timeout. Портал официального опубликования `publication.pravo.gov.ru` тоже может отвечать медленно или блокироваться.

Это не баг нашего кода, а сетевое ограничение источника.

### Что сделано

- Адаптер `agent/adapters/pravo.py`:
  - сборка URL для IPS (`nd=…`) и EO-номеров публикации;
  - `fetch_with_retries` — timeout 90 с, до 6 попыток, экспоненциальный backoff;
  - поддержка `HTTPS_PROXY` / `HTTP_PROXY` и флага `--proxy`.
- `capture_sources.py` автоматически использует pravo-aware fetch для хостов `*.pravo.gov.ru`.
- При неудаче печатается подсказка про geo-restriction.

### Как захватывать pravo с русского выхода

```bash
# Вариант 1: переменные окружения
export HTTPS_PROXY=http://user:pass@ru-proxy:8080
cd agent
python3 capture_sources.py --records ../content/records/records.json

# Вариант 2: флаг
python3 capture_sources.py --proxy http://user:pass@ru-proxy:8080
```

Либо запускать capture на VPS/машине в РФ без прокси.

### Практическая стратегия наполнения

1. **Основной текст** — брать с Минюста (`minjust.gov.ru`), когда файл доступен (уже работает).
2. **pravo.gov.ru** — использовать как дополнительный/контрольный источник, когда есть русский выход.
3. Если pravo недоступен — документ всё равно можно готовить по одному официальному источнику (политика single-source, ветка `content/single-source-fill`).

Не подменять недоступный текст pravo сгенерированным или коммерческим текстом.

## Несколько документов из одного портала

Для каждого документа сохраняется отдельная запись в `records.sources`. Поле `registry_id` ссылается на один из разрешённых порталов в `content/sources/registry.json`, а уникальное поле `key` задаёт каталог доказательств конкретного захвата. Например: `key=koap__pravo_bank`, `registry_id=pravo_law_bank`.

Каталог `content/catalog/core-federal-acts.json` содержит приоритетный перечень федеральных актов. Его записи — только очередь подготовки: статус `not_imported` означает, что текста в базе нет. Каталог не подменяет документы и не считается источником правовой нормы.
